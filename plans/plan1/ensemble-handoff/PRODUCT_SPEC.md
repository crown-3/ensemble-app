# Ensemble 기획서

이 문서는 Ensemble 앱의 기획 내용을 구현자(Claude Code)가 읽고 바로 작업할 수 있도록 정리한 것입니다. 화면 디자인은 `screens/` 폴더에 있고, 화면을 읽는 방법은 `README.md`에 있습니다.

각 항목에는 결정 상태를 표시했습니다.

- **[확정]** 기획자가 직접 결정한 내용입니다. 임의로 바꾸지 않습니다.
- **[가정]** 디자인 과정에서 임시로 정한 내용입니다. 구현 전에 기획자에게 확인합니다.
- **[미정]** 아직 결정하지 않은 내용입니다. 구현 전에 기획자에게 질문합니다.

## 1. 제품 개요

- **[확정]** 이름은 Ensemble입니다. 이전 이름은 AVEC이며, 디자인 파일의 CSS 클래스 이름(`avec-shell`, `avec-side`)에 흔적이 남아 있습니다.
- **[확정]** 컨셉은 "나만의 에이전트 회사 그룹챗"입니다. 사용자는 한 명이고, 직책과 역할이 다른 여러 AI 에이전트가 한 채팅방에 모여 서로 대화하며 결과물을 만듭니다.
- **[확정]** 모든 작업은 사용자의 로컬 컴퓨터에서 진행됩니다. 에이전트는 로컬 폴더의 파일을 읽고, 만들고, 수정합니다.
- **[확정]** 에이전트는 서로 다른 회사의 모델을 사용할 수 있습니다. 예: Claude, GPT, Gemini.
- **[확정]** 사용량은 Claude Code나 Codex처럼 세션당 한도를 기준으로 표시합니다. 따라서 각 에이전트는 Claude Code, Codex 같은 에이전트형 도구의 세션으로 동작한다고 볼 수 있습니다.
- **[미정]** 기술 스택(데스크톱 앱 프레임워크, 저장소 형식 등)은 정하지 않았습니다.
- **[미정]** 에이전트 세션을 실제로 어떻게 실행하는지(CLI 프로세스 실행, SDK 사용 등)는 정하지 않았습니다.

## 2. 핵심 개념

### 2.1 에이전트

- **[확정]** 에이전트는 회사의 직원에 해당합니다. 전역 역할 설정에서 만들고 관리하며, 모든 프로젝트와 채팅에서 같은 에이전트를 사용합니다.
- **[확정]** 에이전트의 속성은 다음과 같습니다.

| 속성 | 설명 |
|---|---|
| 모델 | 모델 제공사. 예: GPT, Claude, Gemini |
| 성능 | 구체적인 모델 버전. 예: GPT Sol 6.1, Claude Opus 5.5, Gemini Flash 3.1 Pro. 선택한 모델에 따라 목록이 달라집니다. |
| 이름 | 표시 이름 |
| 직책 | 예: 기획 리드, 카피라이터, 디자이너 |
| 아바타 이미지 | 사용자가 올린 이미지. 없으면 이름의 첫 글자를 표시합니다([가정]). |
| 페르소나 및 역할 | 에이전트에게 전달되는 프롬프트 |
| 이력 | `{ time: Time, content: string }[]` 형식의 목록 |
| 승인 모드 | 4.1절 참고 |
| 사용할 커넥터 | 4.6절 참고 |

- **[확정]** 이력은 에이전트의 활동이 자동으로 기록되며, 사용자가 각 항목을 직접 수정, 삭제, 추가할 수 있습니다.
- **[가정]** 이력 항목마다 출처를 구분해서 표시합니다: "자동 기록", "자동 기록 · 수정됨", "직접 입력". 이 구분을 저장하려면 이력 항목에 출처 필드가 추가로 필요합니다.
- **[미정]** 어떤 활동을 어느 시점에 이력으로 기록하는지는 정하지 않았습니다.

### 2.2 채팅

- **[확정]** 채팅은 사용자와 에이전트들이 서로 대화하며 결과물을 만드는 하나의 세션입니다.
- **[확정]** 채팅에서는 각 모델이 기본으로 수행할 수 있는 기능을 모두 사용할 수 있어야 합니다. 예: 생각, 파일 생성, 파일 수정, 이미지 생성(모델이 지원하는 경우).
- **[확정]** 채팅을 시작할 때 초대할 에이전트를 고릅니다. 한 명만 초대해도 됩니다.
- **[확정]** 채팅을 진행하는 중에 다른 에이전트를 초대하거나, 참여 중인 에이전트를 내보낼 수 있습니다.
- **[가정]** 에이전트를 초대할 때 읽을 범위를 고릅니다: "이전 대화 전체" 또는 "지금부터".
- **[가정]** 내보낸 에이전트는 이후의 대화를 볼 수 없지만, 프로젝트에서 쌓은 기억은 유지되고 다시 초대할 수 있습니다.
- **[미정]** 여러 에이전트가 있을 때 누가 언제 응답하는지(발언 순서, 멘션이 없는 메시지의 처리)는 정하지 않았습니다. 기획자는 "에이전트에게 어떻게 하라고 직접 지시하면 된다"는 입장이므로, 별도의 계획 승인 기능은 만들지 않습니다.

### 2.3 프로젝트

- **[확정]** 프로젝트는 비슷한 작업을 위한 채팅들의 묶음입니다.
- **[확정]** 프로젝트 안에서 새 채팅을 만들 수 있습니다. 그러나 이미 만든 채팅을 프로젝트 안으로 옮길 수는 없습니다.
- **[확정]** 프로젝트에 속하지 않은 채팅도 존재합니다.
- **[확정]** 프로젝트에는 프로젝트 지침과 참고 파일이 있습니다(4.2절).
- **[가정]** 프로젝트마다 작업 폴더가 하나 있고, 프로젝트의 모든 채팅이 그 폴더에서 작업합니다(4.5절).

### 2.4 메모리

- **[확정]** 같은 프로젝트 안에서 각 에이전트는 자신만의 메모리를 그 프로젝트의 채팅들 사이에서 공유합니다.
- **[확정]** 에이전트는 프로젝트마다 다른 메모리를 가집니다. A 에이전트는 P 프로젝트의 기억을 Q 프로젝트에서 가지고 있지 않습니다.
- **[확정]** 사용자는 메모리 항목을 수정하거나 삭제할 수 있습니다.
- **[가정]** 사용자가 메모리 항목을 직접 추가할 수도 있습니다.
- **[가정]** 메모리 항목은 내용, 기록된 시각, 출처(어느 채팅에서 기록됐는지 또는 직접 추가했는지)를 가집니다.
- **[미정]** 프로젝트에 속하지 않은 채팅에서 에이전트가 메모리를 가지는지는 정하지 않았습니다.
- **[미정]** 에이전트가 무엇을 언제 메모리에 기록하는지는 정하지 않았습니다.

메모리의 범위를 식으로 쓰면 `(에이전트, 프로젝트)` 쌍마다 메모리 저장소가 하나씩 있는 구조입니다.

### 메인 채팅의 구성

- **왼쪽 패널:** 프로젝트 목록(펼치면 소속 채팅), 프로젝트에 속하지 않은 채팅 목록, 검색, 새 채팅 버튼, 전역 역할 설정과 앱 설정 진입
- **가운데 상단:** 채팅 제목, 소속 프로젝트, 참여 인원, 에이전트 초대 버튼
- **가운데 탭 줄:** "메시지"와 "결과물" 탭, 작업 폴더 경로, 채팅별 승인 모드 선택
- **가운데 본문:** 메시지 목록과 입력창
- **오른쪽 패널(멤버 상태):** 기획자의 스케치에 "Discord와 유사하게"라고 적혀 있습니다. 에이전트마다 아바타, 이름, 직책, 모델, 세션 한도 사용량 막대, 상태 점을 표시합니다. 상태 점은 작업 중이면 초록색, 아니면 회색입니다. **[확정]**

### 메시지의 종류

채팅 본문에 나타나는 요소입니다. 디자인은 `Main.dc.html`에 모두 들어 있습니다.

- 사용자의 메시지
- 에이전트의 메시지(아바타, 이름, 직책 표시)
- 생각 표시(접힌 상태, 소요 시간 표시)

- 시스템 알림(예: 에이전트를 초대함)
- 작업 중 표시

## 4. 기능 상세

### 4.1 승인 모드 [확정]

에이전트가 작업을 실행하기 전에 사용자의 승인을 받을지 정합니다. 채팅별로도, 에이전트별로도 설정할 수 있습니다.

- **[가정]** 채팅별 설정은 세 단계입니다: "모든 작업을 승인 후 실행", "파일 수정만 자동 승인", "모든 작업을 자동 승인".
- **[가정]** 에이전트별 설정은 세 가지입니다: "채팅 설정을 따름", "항상 승인 요청", "항상 자동 승인". 에이전트별 설정이 채팅 설정보다 우선합니다.
- **[가정]** 앱 설정에 새 채팅의 기본 승인 모드가 있습니다.
- **[가정]** 승인 요청 카드에는 "승인", "거절", "이 채팅에서 이 에이전트는 항상 승인" 버튼이 있습니다.

### 4.2 프로젝트 지침과 참고 파일 [확정]

- 프로젝트 지침은 해당 프로젝트의 모든 채팅에서 모든 에이전트에게 전달되는 텍스트입니다.
- 참고 파일은 에이전트가 해당 프로젝트에서 항상 참고하는 파일 목록입니다.

### 4.3 전역 지침 [확정]

- 모든 프로젝트, 모든 채팅에서 모든 에이전트에게 전달되는 텍스트입니다.
- **[가정]** 지침의 적용 순서는 전역 지침, 프로젝트 지침, 에이전트의 페르소나입니다.

### 4.4 멘션 [확정]

- 입력창에 `@`를 입력하면 자동완성 목록이 나타납니다.
- 멘션할 수 있는 대상은 에이전트, 파일, 커넥터입니다.
- 채팅 메시지와 입력창에 작성된 멘션은 강조 표시합니다.
- **[가정]** 자동완성 목록은 대상의 종류별로 구역을 나누고, 위아래 화살표로 이동하며 Enter로 선택하고 Esc로 닫습니다.
- **[가정]** 강조 표시의 스타일은 `Main.dc.html`에 있습니다. 사용자의 파란 말풍선 안에서는 반투명한 흰 배경, 그 밖에서는 연한 파란 배경(`#d6e6fb`)에 진한 파란 글자(`#0a4fa8`)입니다.

### 4.5 로컬 폴더 연결 [확정]

모든 작업이 로컬 기반이므로 반드시 필요한 기능입니다.

- **[가정]** 프로젝트를 만들 때 작업 폴더를 지정하고, 프로젝트의 모든 채팅이 그 폴더에서 작업합니다.
- **[가정]** 프로젝트에 속하지 않은 채팅은 채팅을 만들 때 작업 폴더를 직접 고릅니다.
- **[가정]** 에이전트는 작업 폴더 안에서만 파일을 읽고, 만들고, 수정합니다.

### 4.6 커넥터 [확정]

에이전트가 외부 앱의 자료를 읽거나 작업할 수 있게 하는 연결입니다. 기획자가 구현 방법에 대한 도움을 요청한 항목입니다.

권장하는 구현 방식은 MCP(Model Context Protocol)를 활용하는 것입니다. Claude Code, Codex, Gemini CLI가 모두 MCP 서버를 지원하므로, Ensemble은 연결 정보를 관리하고 전달하는 역할만 맡습니다.

1. Ensemble이 MCP 서버 목록(이름, 실행 명령 또는 URL, 인증 정보)을 한곳에 저장합니다. 앱 설정의 커넥터 구역이 이 목록을 편집합니다.
2. 에이전트마다 사용할 서버 이름 목록을 저장합니다. 에이전트 편집 화면의 체크박스가 이 값입니다.
3. 에이전트의 세션을 시작할 때, 허용된 서버만 담은 설정을 도구별 형식으로 만들어 넘깁니다.
4. OAuth가 필요한 서버의 인증은 각 도구의 로그인 흐름에 맡기는 편이 간단합니다.

도구별 MCP 설정 형식(파일 위치, 키 이름)은 이 문서에서 검증하지 않았습니다. 구현 전에 각 도구의 최신 공식 문서를 확인해야 합니다.

### 4.7 결과물 모아보기 [확정]

- 채팅 상단에 Slack처럼 탭을 두고, "결과물" 탭에서 해당 채팅의 에이전트가 만들거나 수정한 파일을 모아 봅니다.
- **[가정]** 종류별 필터(전체, 문서, 이미지)가 있고, 항목마다 만든 에이전트, 버전, 수정 시각, 작업 폴더 안의 경로를 표시합니다.
- **[가정]** 파일을 열면 결과물 뷰어 패널에서 내용, 버전 탭, 버전 기록을 볼 수 있습니다.

### 4.8 모델 계정 연결과 사용량

- **[확정]** 사용량은 세션당 한도를 기준으로 합니다.
- **[가정]** 앱 설정에서 모델 제공사별로 계정을 연결합니다. API 키 입력 방식이 아닙니다.
- **[가정]** 같은 모델을 사용하는 에이전트들은 한도를 함께 사용합니다.
- **[미정]** 한도의 초기화 시각과 남은 양을 각 도구에서 어떻게 읽어오는지는 정하지 않았습니다.

## 5. 만들지 않는 기능

기획자가 명시적으로 제외하거나 보류한 기능입니다. 요청이 없으면 구현하지 않습니다.

| 기능 | 상태 | 이유 |
|---|---|---|
| 계획 승인(실행 전에 단계별 계획을 승인) | 제외 | 사용자가 에이전트에게 직접 지시하면 되는 부분입니다. |
| 진행 상황 표시(에이전트별 할 일 목록) | 보류 | |
| 예약 작업 | 보류 | |
| 브라우저와 컴퓨터 조작 | 제외 | 구현 부담이 큽니다. |
| 모바일에서 작업 지시, 음성 대화 | 제외 | 구현 부담이 큽니다. |
| 결과물을 웹앱으로 게시 | 제외 | 구현 부담이 큽니다. |
| 스킬(에이전트별 재사용 절차) | 미결정 | 기획자가 의견을 주지 않았습니다. |

## 6. 데이터 모델 초안

기획 내용에서 도출한 초안이며 **[가정]** 입니다. 필드 이름과 저장 방식은 구현하면서 조정합니다.

```ts
type Agent = {
  id: string;
  name: string;
  title: string;                 // 직책
  provider: string;              // 모델: "claude" | "gpt" | "gemini" 등
  model: string;                 // 성능: "opus-5.5" 등
  avatarPath?: string;
  persona: string;               // 페르소나 및 역할 프롬프트
  history: HistoryEntry[];
  approvalMode: "inherit" | "always-ask" | "always-auto";
  connectorIds: string[];
};

type HistoryEntry = {
  time: string;                  // 기획서의 Time
  content: string;
  source?: "auto" | "auto-edited" | "manual";   // [가정] 화면의 출처 표시용
};

type Project = {
  id: string;
  name: string;
  description?: string;
  folderPath: string;            // 작업 폴더
  instructions: string;          // 프로젝트 지침
  referenceFiles: string[];      // 참고 파일 경로
};

type Chat = {
  id: string;
  title: string;
  projectId: string | null;      // 만든 뒤에는 변경할 수 없음
  folderPath: string;            // 프로젝트가 있으면 프로젝트의 폴더
  memberAgentIds: string[];      // 진행 중에 초대와 내보내기로 변경됨
  approvalMode: "ask-all" | "auto-edits" | "auto-all";
};

type MemoryEntry = {
  id: string;
  agentId: string;
  projectId: string;             // (agentId, projectId) 쌍이 메모리의 범위
  content: string;
  createdAt: string;
  source: { chatId: string } | "manual";
};

type Connector = {
  id: string;
  name: string;
  mcp: { command?: string; args?: string[]; url?: string };
  connected: boolean;
};

type GlobalSettings = {
  globalInstructions: string;    // 전역 지침
  defaultApprovalMode: Chat["approvalMode"];
  theme: "light" | "dark" | "system";
};
```

## 7. 구현 전에 기획자에게 확인할 질문

1. 기술 스택은 무엇으로 하나요? 로컬 파일과 CLI 세션을 다루어야 하므로 데스크톱 앱 형태가 필요합니다.
2. 에이전트 세션은 어떤 방식으로 실행하나요? 각 도구의 CLI를 프로세스로 실행하는 방식인지, SDK를 사용하는 방식인지에 따라 구조가 달라집니다.
3. 여러 에이전트가 참여한 채팅에서 멘션이 없는 메시지는 누가 응답하나요?
4. 에이전트끼리 주고받는 대화는 어떤 조건에서 멈추나요?
5. 프로젝트에 속하지 않은 채팅에서도 에이전트가 메모리를 가지나요?
6. 메모리와 이력은 누가 언제 기록하나요? 에이전트가 스스로 기록하는지, 채팅이 끝난 뒤에 앱이 요약해서 기록하는지 정해야 합니다.
7. 이 문서에 [가정]으로 표시한 항목들을 그대로 진행해도 되나요?
